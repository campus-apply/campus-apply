# 口径访谈法

> 方法部分改编自 grilling（Matt Pocock，MIT），见仓库根 `THIRD_PARTY_NOTICES.md`。题库是本项目自己的。

## 方法
把要定的事画成一棵"决策树"：每个决定下面挂着依赖它的下一层决定。按"轮"问：这一轮只问前提已经定了、现在就能回答的问题（前沿），一轮里把前沿全问完，每题编号、给出你的推荐答案和理由；等用户答完，重新算前沿再问下一轮。前沿空了就结束。事实自己查（读文件、看简历、查网页），只把"决定"交给用户。用户不熟的概念先用一两句白话解释再问。

每题格式：

```
❓ Q1 - 题目：题干，可以给 A/B/C 选项
➡️ 推荐：选哪个，为什么（一两句）
```

## 通用口径题库（初始化时问一次，答案写进 rules.json 和事实库）
题目固定，推荐答案要按用户背景调：下面括号里的推荐是给"有客户项目、数字多、口径敏感"的人准备的；理工背景、论文和开源项目多的人，隐名、数字来源这两题的推荐往往相反（论文、实验室、导师、项目名本来就该点名，数字来自自己的实验记录），先看事实库或简历再给推荐，别照抄。
1. 隐名：简历里客户/合作方写真名还是"某行业某客户"？（推荐：隐名写行业，`anonymize_clients: true`，真名列进 `sensitive_terms`）
2. 数字来源：哪些数字是自己校对过的、哪些是听说的？听说的要不要写？（推荐：只写校对过的，`number_source_check: true`）
3. AI 辅助怎么写：你用 AI 帮忙写过的脚本、做过的图、起草过的稿，在简历里描述这件事时用什么说法？比如"用Python写了脚本"还是"借助AI编写脚本"。这只是一个措辞约定，不是什么开关。（推荐：统一写"借助AI编写"，存到 `ai_script_phrase`，理由是面试被追问时对得上）
4. 角色边界：哪些项目自己不是主责（主笔是别人、只做素材、没上线、没成交）？列出来写进事实库"边界"行，并把对应表述放进 `forbidden_claims`。
5. 不想写的经历或信息：有没有不想出现在任何简历里的经历、人名、单位？→ `sensitive_terms`。
6. 文风：书面还是口语；接不接受"第一、第二"结构；每条最多几个数字；禁用哪些词（先给默认表让用户增删）；书名号、引号里的标题名（稿件名、项目名）是否豁免禁用词 → `banned_words`、`max_numbers_per_bullet`、`banned_words_exempt_in_quotes`、`style_notes`。
7. 格式偏好：一页还是不限；中英文之间留不留空格；数字全角半角 → `style_notes`。
8. 隐私：手机号、证件号、住址不进事实库；网申里这些字段由用户自己填。确认用户知道。
9. 时间口径：网申里教育经历的起止月份要首尾相连（本科结束月的下一个月就是硕士开始月），连续的工作经历同理；简历 docx 上可以按学校官方月份写。问清用户的口径写进 `style_notes`。

## 求职偏好题库（初始化时问一次，答案写进 `campus-apply.json` 的 `preferences`；job-screen 每次只问有变化的）
1. 投什么：校招正式批 / 提前批 / 实习 / 社招，哪些要投 → `apply_types`。
2. 岗位类型：管培生（轮岗型）、专业岗、研究岗、销售型岗，哪些愿意、哪些坚决不投 → `role_types_ok` / `role_types_no`。（例：用户可能根本不想报"培训生"，这一题问清楚，筛选时按标题直接排除并写明原因。）
3. 地点：接受哪些城市，不接受哪些 → `locations_ok`。
4. 海外线：国内业务还是海外业务，接不接受海外轮岗 → `overseas_ok`。
5. 语言：英语能不能作为工作语言，小语种有没有 → `english_working_ok`；小语种写进事实库。
6. 提前入职实习：有的岗要求毕业前提前到岗实习，能不能接受、最早什么时候 → `early_onboarding_ok`。
7. 其他硬约束（户口、家庭、健康、已有 offer 的截止时间等，用户愿意说的才记）→ `notes`。

## 个人档案题库（初始化时问一次，答案写进 `campus-apply.json` 的 `profile`，网申时直接用）
各站网申都要的基本字段，一次问清：性别、出生日期、所在地（当前城市）、政治面貌、最高学历与预计毕业时间、期望城市、期望月薪与年薪（税前，K/月、W/年）、获取招聘信息的常用渠道、有无内推码来源。**证件号、密码永远不存**，网申时由用户手填；用户在对话里给过的证件号不写进任何文件。档案在本地工作目录，`.gitignore` 已忽略，提醒用户不要把工作目录放进公开仓库。

## 单次投递题库（resume-tailor 里只问这份 JD 新引出的）
- JD 反复强调某项能力（如供应链、硬件、海外市场），事实库里既没证实也没否定，且与用户背景相邻：问"你有没有相关经历，哪怕是课程或小项目？"
- JD 点名要某种材料（作品集、代码仓库、成绩单）：问有没有、在哪。
- 这家公司要不要提某个客户或项目的真名（比如投给曾服务过的客户）：问一句，答案只对本次投递生效，记在投递目录 `jd.md` 末尾"本次口径"。
- 一轮最多 5 题，一次问完，不逐题追问；答案写回事实库（【用户口述 日期】）或投递目录。
