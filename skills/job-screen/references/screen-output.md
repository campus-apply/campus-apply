# 筛选输出格式

按顺序产生：`岗位清单_<日期>.md`（第 3 步，全量）→ `jobs/<岗位>.md`（第 4 步，每个读过的 JD）→ `岗位筛选_<日期>.json`（第 5 步，唯一数据源）→ `scripts/screen_render.py` 由它渲染 `岗位筛选_<日期>.md`、工作目录根的 `<公司>_岗位筛选_<日期>.xlsx` 和对话里贴的表（`--print`）。三处同列同源，表格不手写。

## 岗位筛选_<日期>.json（唯一数据源）
列表，每项的基础键：`tier`（建议投/可投但有缺口/不建议/未读）、`title`、`cat`、`org`（单位/部门）、`loc`、`nature`、`date`、`edu`、`major`、`major_match`（匹配 / 本科匹配 / 硕士匹配 / 都不匹配 / 相邻）、`lang`、`pri`、`duty`、`why`、`gap`、`url`、`unread`（真=没读详情）。硬要求字段由模型读 JD 填。
JD 里读到的其他硬信息用中文键直接加（如 `招聘人数`、`届别`、`截止日期`、`薪资`），渲染时自动成为额外列，按首次出现的顺序排在基础列之后；哪个岗位没有就不写这个键，格子留空；"若干"照抄"若干"，页面没写的不填 0。

## 岗位清单_<日期>.md（全量，含状态列）

```
# <公司> 岗位清单（YYYY-MM-DD）
站点：<域名>；结构：门户 → 类别 → 列表 → 岗位页；共 N 个类别 M 个岗位。
站点规则（原文摘录，标出处页）：可投几个岗 / 能否修改 / 内推码 / 入职时间 / 面试形式。
用户偏好（来自 campus-apply.json.preferences）：投什么、要与不要的岗位类型、地点、海外、语言、提前入职。

| # | 岗位 | 类别 | 地点 | 性质 | 发布日期 | 状态 | 原因 | 链接 |
|---|---|---|---|---|---|---|---|---|
| 1 | … | 产品类 | 深圳 | 全职 | 2026-08-18 | 打算读 | 标题与偏好相符 | … |
| 2 | … | 产品类 | 深圳 | 全职 | 2026-08-18 | 按标题排除 | 设计类岗位，用户不投 | … |
```
状态只有两种："打算读"和"按标题排除：原因"。用户圈定后，把用户改动的行标注"用户捞回 / 用户排除"。

## 岗位筛选_<日期>.md（由 screen_render 生成：读过的岗位表 + 排除清单；末尾"问答与定稿"由 agent 追加）

## 提问三条件（同时满足才问）
1. 是 JD 的硬门槛或反复强调的要求；
2. 事实库既没证实也没否定；
3. 与用户已有背景相邻（用事实库判断：文科背景不问工科要求，没做过硬件不问电路）。

只对用户在第 5 步说"重点考虑"的岗位问；每次筛选攒成一轮，最多 5 题，一次问完，每题带"我猜是没有"之类的推荐答案。
