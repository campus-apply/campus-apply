# 资料复用、状态更新与用户交接

## 资料有来源，使用有范围
- 先复用已确认且带来源的事实库和相关记录，缺项才读原件；用户指定先用旧记录时遵循这个来源顺序。旧申请能提供事实素材，当前页面要求决定素材放在哪个字段；自述仍走 resume-tailor 的确认流程。
- 月份、名称、级别等来源冲突时，把不同说法及各自出处列给用户，不静默覆盖。用户明确答复后带日期写回事实库或本次口径；不把文件修改时间当作更可靠的答案。

## 完成就更新原记录
- 开始或续作时读当前执行清单、填写日志和待决文件，不重建一份清单绕过未完成项。实际完成后勾原行并记证据位置；等待答复的步骤先写等待时间，回答到达且步骤要求满足才勾。
- 用户回答后按原编号或标题把待决原项移到“已定”，写答复与时间；引用这项决定的公司目录、岗位目录或工作区记录同步关闭，保留关联路径。相同答案不再追问，尚无证据的完成状态不补勾。
- 同名或相似记录无法确定是否同一事项时，保留待核对并说明。不要凭标题相似或文件较新自动合并、覆盖。
- 接手或交付时如需检查一致性，运行 `python3 <campus-apply目录>/scripts/workspace_state.py --workspace <工作目录> --scope <相对 applications 子目录>`；全工作区检查可省略 `--scope`。工具只读，JSON 告警带路径、行号、类型及关联路径；退出 0 表示未发现可识别问题，1 表示待核对，2 表示参数或读取错误。无告警不等于工作完成，逐项结合原记录判断，不必每字段都跑。

## 关键内容在工具结束后的交接中说明
- 依赖用户决定的写入立即停；可先做与答案无关的只读探测、整理和日志更新。工具结束后，用一条收尾消息交接：已完成 / 未保存状态，影响本次操作的限制或冲突，仍需用户决定的事项与建议。
- 即使中途已说过关键限制，收尾也重新说清，让用户在获得控制权时能看到；依赖操作与关键待答项不能藏在工具调用前的进度消息里。交接后结束本轮等待答复，再根据回答继续。
- 普通进度不变成确认节点；用户已授权的独立工作照常完成。可依据阻塞、错误或耗时变化报告进度，不为固定反馈频率增加步骤。

## 反馈摘要交付
用户明确要反馈包后，检查生成的摘要无待补占位。能从记录确认的内容列证据，缺会话或计时信息写“未记录 / 无法从现有资料确认”。当前打包工具版本不代表历史会话实际载入版本；已知与未知分别注明，不编模型、停顿次数或完成状态。
