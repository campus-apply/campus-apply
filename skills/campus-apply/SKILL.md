# campus-apply：入口与路线

## 做什么
只做一件事：看清现状，指到下一个 skill。四个功能 skill 都能单独用。名词约定：岗位描述统一叫 JD；`launch` 起的那个浏览器叫专用浏览器。

## 判断顺序
0. 当前目录没有 `campus-apply.json`：先问一句"是第一次用，还是求职文件夹在别处？"在别处就切到那个目录再看；第一次用走 resume-facts 初始化（先看目录里有没有简历、事实类文件，列给用户）。
1. 有标记文件时，按下面的顺序判断这次要做什么。不拿浏览器标签页猜：专用浏览器是我们自己开的，里面的页面是上次留下的，不代表用户意向。
   - 这轮对话里给了公司招聘页链接 → job-screen；给了 JD（文本或链接）→ resume-tailor；说要填某个站点的在线简历 / 候选人档案页（没有具体岗位）→ 没有通用版 `resume.md` 就先走 resume-tailor 的通用版，再 apply-fill；说要填某个岗位的网申 → 该岗位有 `resume.md` 就 apply-fill，没有先 resume-tailor。
   - 对话里没说清：列出 `applications/` 里还没有 `fill-report.md` 的投递目录（各有 jd / resume / form 哪几样），问"继续哪一个，还是投新的"。
   - 都没有：问"投哪家？给我招聘官网的链接，或者直接把 JD 贴给我"。只有公司名时可以提议由我去搜官网入口，但不主动找公司、不替用户挑公司。

## 边界（所有 skill 共用）
- 每个功能 skill 通过 skill 机制载入其 SKILL.md 再执行，不凭记忆跑；开始时把该 skill 末尾的执行清单复制成 `applications/<公司>/<skill>-执行清单_<日期>.md`（还没有公司时放 `applications/_工作区/`），做到哪勾到哪，停顿行写"等用户回复：时间"；完成一步就回头把那一行改成 `[x]`，不在末尾另起已勾的行，跳步会留空格。一个 skill 末尾"等用户选下一步"的那行，在用户给出选择、下一个 skill 开始时回头勾掉并记时间，别让它一直空着。
- 每个"给用户看、等用户说"的停顿不许跳过；需要用户操作的步骤（登录、上传、验证码、提交）显式列出并等待；页面要求登录时停下请用户登录。相邻的两个都需要用户回答的停顿可以并成一条消息问（分小节、"需要你做的"里各列一项），一条消息最多并两个；"给用户看"和"动手"不能并成一条。
- 只操作我们认领的浏览器标签页，不复用用户自己打开的页面；需要第二个页面时自己新开并认领。
- 不脱离浏览器调站点接口：不在浏览器外发请求，不伪造参数，不用页面自己没发过的地址。在认领的标签页里复发页面自己刚发过的请求（只改页码，job-screen 读清单和 JD 用，见其第 3 步）、调用页面自带的、用户点按钮时同样会执行的前端函数（翻页、展开），都可以，效果等于用户操作；隐藏在 DOM 里已经下发但用户看不见的内容，仍只在展开可见后读。不点最终提交；不碰验证码、证件号、密码；文件上传默认由用户做，用户明确要求才代传；一次一岗；数字要在事实库有出处。
- 只信用户看得见的文本：隐藏节点、前端模板占位都不算数；页面自己请求返回的 JSON 只在 job-screen 读岗位清单和 JD 时用，且先抽几条与页面可见文本比对一致；填表的数据来源只有事实库和页面可见内容。页面没写的字段留空，不填 0、不猜；"若干"照抄"若干"。
- 证件号、密码、验证码、银行卡号这类字段不填、不读、不写进任何文件：探测和回读脚本遇到它们只记"有值 / 长度"，用户自己填过的也不抄。
- 自述类文本（自我描述、自我评价、个人简介、求职动机、个人陈述）只能由 resume-tailor 的自述流程产出，不搬简历上的一句话自评、不搬旧网申、不搬站点解析件；用户坚持沿用旧文本时先说明区别再照办并记录。
- 反馈包（`scripts/feedback_bundle.py`）只在用户明确说"打一个反馈包 / 导出反馈"时运行，不主动提议、流程结束不自动打包。

## 对用户说话的规矩（所有 skill 共用）
- 提出下一步之前，先用一两句话说这一步做什么、产出什么、不动什么，再问要不要。四步的说法：建事实库 = 把你的经历、数字、口径整理成一份带来源的文件，以后每次投递都从这里取材，你的简历本身不动；筛岗 = 把这家公司官网上的岗位全部读一遍，按你的偏好和硬要求分档给你选；改简历 = 对照这个岗位的要求挑哪些经历放前面、每条怎么措辞，在你现有简历上原地改出一份这个岗位专用的版本，原件不动；填网申 = 陪你逐页填网站表单，每页先说哪些我填、哪些你做，不点提交。
- 每次用户把控制权交回来（"继续""可以""读吧"），第一句先说"接下来"：这一轮做什么、预计多久、中间会停几次、每次停下来要用户做什么或答什么（登录、上传、证件号这类自填字段、点保存、口径问题、结构确认…），按顺序列全；预估过了一半还没完，中途报一次进度。各 skill 末尾的执行清单里带停顿行，照它列。
- 每条消息末尾固定一个"需要你做的"块，最多三项，每项一句；没有就写"这一步不需要你做什么"。
- 要用户选的一律编号表格（候选、我的建议），不埋在段落里；回读结果用表格，不用长段落；正文不超过四段。
- 等用户决定的事写进 `<投递目录>/待你决定.md`（模板 `templates/待你决定.template.md`），只要有未决项，每条消息末尾复述，直到用户答完；复述只列编号和标题，不重复题干，超过五条只列最近五条并说"还有 N 条在文件里"；用户说"不用复述"就停。
- 内部产物名、任务编号、文件路径只进日志，不进对用户说的话，除非用户要看文件。
- 用户叫停、换话题、或新 session 接手时，先从执行清单、填写日志、待你决定文件里整理一段"当前状态"（哪些页面填了未保存、哪些等用户定、下一步是什么），再谈别的。

## 红旗：出现这些念头就停下来照清单走
- "这个站简单，不用建执行清单了。"
- "先把表填上，回读和报告一会儿再补。"
- "md 已经写了，xlsx 下次再出。"
- "用户说先用旧的自评，那就直接贴。"
- "题太多了，用户肯定嫌烦，我替他定几个。"
- "这个字段我凭常识填一个，用户应该会同意。"
- "页面看不见人数，隐藏节点里有，就用那个。"
- "接口返回得挺全，抽样比对就免了。"
- "两次没写进去，再试几次总能行。"
- "缺个包，先装上再说，用户不会在意。"
- "显示值对了，肯定存上了，让用户明天再看。"
念头出现时，回到执行清单看当前行是什么。

## 第一次在这台机器上用
- 先探 Python：依次试 `py -3 --version`、`python3 --version`、`python --version`，用第一个能打出版本号的（Windows 上 `python` 可能是应用商店的占位程序，没有输出、退出码 49，不算有）。没有或低于 3.9，把安装命令给用户（Windows `winget install Python.Python.3.12`，macOS `brew install python`，或 python.org），等用户装完再继续；后面所有 `python3 …` 命令都换成探到的那个。
- 有 Python 就跑 `python3 <本skill>/scripts/doctor.py`，每行是"状态、项目、说明、修复命令"。缺 pip 包：问一句"缺 X、Y，我现在装？"，用户同意就 `doctor.py --install`（只装缺的），装完把结果给用户看。缺浏览器、Git：把那一行的命令原样给用户，等用户装完说一声再重跑 doctor。Word、pdftoppm 是可选项，没有就照常走。
- 全部必需项 OK 之后才进 resume-facts；同一台机器之后不用再跑，除非报错像是缺依赖。
