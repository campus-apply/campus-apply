# 现场处理原则

每个站点的板块划分、控件、弹窗、分步流程都不一样。本 skill 只给办法，不给死代码：填写脚本每站现写，`lib_antd3.js` 只是一套参考实现。具体选择器以探测结果和现场 DOM 为准。

## 先等页面稳定
- 刷新或导航后表单是分批渲染的，头几秒只有少数控件；探测至少做两次、间隔两秒，控件数不再变化才算稳定，否则会把没加载完的页面当成空表。

## 控件类型先探清楚
- 静态分类：看标签、placeholder、class、有没有下拉箭头或日历图标，把每个控件归为文本、纯下拉、可搜索下拉、日期面板、级联、复选、文件之一。`probe.js` 标成 `dropdown?` 的只是"像下拉"（旁边有显示值元素、箭头图标或弹出属性），是纯下拉、可搜索还是级联要靠行为探测定；`disabled` 的字段写不进，`readonly` 的多半是面板类。
- 分不出来的做一次无害的行为探测：点一下看有没有面板或菜单出现，输一个字符看有没有建议项，然后恢复原值并关掉。只在表单还是空的时候做。
- 结论写进填写计划和站点笔记。可搜索下拉（年、月、学校名称这类）最容易被当成文本框：值要靠点菜单项才算选中，选中后显示在另一个元素里，输入框本身可能是空的。

## 面板必须收起
- 每打开一个下拉、日历、级联面板，同一步骤内必须关掉并验证已关。先找到这个输入框自己的面板（按位置：横向重叠、纵向紧挨），选完核对显示值，面板还开着就按下面的顺序试，第一个奏效的记进站点笔记，同一站后面直接用：再点一次输入框 → 点该字段的标签 → 让输入框失焦 → 点所在板块的标题 → 点页面上任意一个静态标题。
- 禁止 `document.body.click()`，禁止键盘事件。
- 整页填完再检查一次"打开的面板为零"，不为零不算完成。

## 脚本要能整页重跑
- 按板块写成幂等函数：先保证条目数够，再逐条比对现值与目标，只写不一致的；字段间随机停顿；每个板块写完回读。
- 填写日志里留全量目标值，出事故能整页重填。

## 回读以显示值为准
- 下拉读显示值元素，文本读 `value`，日期读显示值；输入框 `value` 为空不等于没填。
- 证件号、密码、验证码、银行卡号这类字段回读只记"有值 / 长度"，不把内容写进回读文件或日志，用户自己填的也一样。
- `disabled` 的字段（常见于账号级的姓名、手机、邮箱）写不进去，探测时先标出来，告诉用户去账号设置页改。
- 校验提示（"必填项未填写"）可能滞后于实际值，不能拿它当填没填的判据。
- 条件字段（选了某项才出现的字段）探测不到，填完一轮回读才会看到，要再填一轮。

## 分步、暂存、弹窗
- 分步表单（"下一步""上一步"）：一步一个脚本，写完本步回读通过后才进下一步；点前跑 guard，点后等页面稳定再探测。"下一步"由用户点还是我点，第一次遇到时问用户定一个规矩。
- "暂存""临时保存""保存草稿"默认不点，用户明确说要点才点；真正的"提交""投递"永远不点。
- 弹窗：先分清是我们触发的（删除确认、日期面板）还是站点弹的（引导、公告、验证）。前者一次触发一次处理；后者只读内容告诉用户，让用户决定关不关。
- 自动识别简历附件带出的占位内容只当占位，逐字段重写。
- class 带发版哈希后缀时用前缀匹配 `[class^="xxx-"]`。
