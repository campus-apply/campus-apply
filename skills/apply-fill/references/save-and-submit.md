# 保存、刷新与提交

## 刷新或导航之前
- 先问一句"确认已保存？"，得到明确回答再动。用户说"填好了"不等于"保存了"。
- 刷新前把当前页所有值回读一遍留底到填写日志。
- 刷新后逐字段对比，丢了就用留底重填。

## 保存后
- 文本域上限未知时，用户保存后刷新页面重新探测，逐字段核对字数与写入是否一致，截断了就压缩重填，实测上限记进站点笔记。
- 多条目的板块（经历、项目、获奖）保存后站点可能重排顺序，比对时按关键字段（名称加起止时间）把条目配对，再逐字段比，不按位置比，否则会报一堆假差异。
- 比对的是文本内容，不只是字数：站点保存时可能把敏感词换成星号、截断长文本、改写标点和空格，这些改写会原样进入投递。发现任何不是我们写入的改动，停下来把改前改后贴给用户，让用户定怎么改措辞。
- 自述、自我评价、求职信这类代表用户口吻的长文本，填之前把全文贴在对话里给用户看过；经历描述类已在改简历阶段过目的可以只报字数。

## 提交之前
- 把所有页面的字段回读成一张表给用户 → 用户点"预览" → 我读预览页与表比对（也查星号、截断、改写）→ 有出入指出 → 用户点"提交"。"预览""提交"都由用户点。
- 请用户点某个按钮之前，看一眼它会不会开新窗口（链接带 `target=_blank`、点击处理里有 `window.open`、或按钮语义是预览 / 打印 / 导出 / 下载）。觉得可能就先提醒："这一下可能弹出新窗口，被浏览器拦住的话地址栏右边会有提示，点允许再看。"用户点完用 `list` 看有没有新标签页，没有就再提一次。
- "暂存""临时保存""保存草稿"默认不点；真正的"提交""投递"永远不点。
