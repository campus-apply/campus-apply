# 每页循环：当前证据、真实目标、增量观察

## 开始
1. 认领标签页，复制执行清单、建立 fill-log；读取本域名已核实的投递/草稿/解析记录，结构重新现场看。
2. guard → survey，只读检查当前候选、上传位、登录与阻塞状态。候选表不是已经确认的字段表，UI含义由agent判断。
3. 有上传位第一件事是传简历 PDF 附件：先留底、上传已确认PDF、观察解析前后差异；传附件永远排在填字段之前；同一文件不重传。见 upload-and-parse。

## 观察当前阶段
用DOM与页面一起确认字段/条目组/可操作控件。看不清或报告矛盾就主动screenshot并看图；图定结构，数值与文字原文由DOM读取。
按已确认素材数量先添加需要的条目组，再观察。默认probe-options只列证据，原生select直接读标准选项；agent确认哪几个控件应打开，再用 --only 点名。已有值可以开关菜单读选项，不试选、不清空、不假设所有字段未来都已露出。
记录页面明示的范围和字数限制；未触发的校验写未核验。渲染稳定只证明这一刻结构稳定。

## 集中确认
当前阶段需要用户决定的值/意愿/材料集中交接；已答的不重问。结构、面板和显示节点由agent自己判断，不让用户替agent排查DOM。
真实目标值从resume.md/form.md与已确认事实取，下拉值有现场选项出处。生成plan-skeleton --from-options骨架，agent确认哪些候选是真字段，填kind/value；歧义选择panel_selector、option_selector，显示来源不明用display_selector。候选文字相同不代表同一节点。

## 执行与回读
fill是默认批量执行入口，一份计划只写当前激活步骤。已经观察到会变分支的真实选择先单独执行；其他独立字段可以批量。
报告 needs_observation / structure_changes 时，已写字段按实际结果保留，剩余旧计划不执行：survey重新看当前状态，按新增/替换字段补计划。新信息真需用户决定才集中再问，已有答案继续沿用。
报告 candidates / close_candidates / display_unknown 时，先读完整证据、主动截图判断。selector由agent根据本页DOM给出，每次执行实时唯一校验；旧handle不持久用作重建节点的身份。options_unverified是来源未验证的标记，不是验证完成。
工具无法表达的特殊控件可用现有click/type/exec/stage现场操作；先确认目标和后果，值有来源，执行前查可见/连接/遮挡，执行后只读验证。不得因工具失效无限尝试，也不得为赶进度编值。
两次写入不对按control-failure交接；原值未知不补填/清空。已写值、当前回读、面板状态分别报告，不能把未关或未知报成没写。

## 收尾
更新fill-log和原清单，明确已填/未决/未知/未保存。用户保存后刷新比对；预览和最终提交按save-and-submit。写fill-report、站点有代价的事实、log.txt，不把一次结构结论推广到其他页面。
