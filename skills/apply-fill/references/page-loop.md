# 每一页的循环

这一个循环走遍每一页：**看这一页 → 说清楚 → 该用户做的等用户 → 该我做的做完回读 → 记一笔 → 下一页**。

## 开始（整个 skill 一次）
1. 认领标签页，把 `checklist.md` 的执行清单复制成 `<投递目录>/apply-fill-执行清单_<日期>.md`，建 `fill-log.md`（`../templates/fill-log.template.md`）。→ `claim-and-tabs.md`
2. 读 `site-notes/<域名>.md`；跑 guard，要登录就请用户登录。→ `claim-and-tabs.md`
3. 只读探测入口页，把已知、未知、建议顺序和代价告诉用户，等用户同意再动。→ `upload-and-parse.md`
4. 每进一个表单页先跑 `survey` 探一次上传位：**有上传位就第一件事是传简历 PDF 附件**（默认由我代传，用户说"我自己传"就等他），等站点解析完做前后对比，再开始填这页的字段；本页没有上传位就记一笔继续填，不停下来问。附件区已经有文件时先读它是哪一份，同一份就不重传。顺序不变——在有上传位的页面上，传附件永远排在填字段之前，因为解析会覆盖空字段。`form.md` 在第一次探过字段之后写——先看解析把哪些字段填掉了，剩下哪些长文本要自己写。→ `upload-and-parse.md`

## 探完再填（这一页的硬顺序）

一个人填表是这样的：传简历、从上往下看一遍、要加几条就先点几下添加、把每个下拉点开看有哪些选项、
该问的一次问清楚，然后从头填到尾。**不是填一半发现还有东西没看过，回去点开看看，再接着填。**

所以这一页的顺序是死的：**探完 → 问完 → 填完**。

- **探完**的定义有四条，缺一条就不算完：① 条目组按素材数量**先点满**（加完组再探，否则后加的组里的字段不在计划里）；
  ② 每个下拉用 `probe-options` 读回完整选项；③ 条件字段（选了某个值才出现的）在探测时就触发出来；
  ④ 长文本的三层字数限制都拿到。
- **问完**：这一页所有要用户定的事，**在写入任何字段之前**一次问清。
- **填完**：一份计划覆盖这一页所有能填的字段，一次跑完。**填写阶段不再探测**——发现有没探到的，
  说明探测没做完，回到探测阶段补，而不是边填边看。

整页为空才放开动页面（点添加、开下拉、触发条件字段）。表单里已经有内容时，探测退化成只读，
条件字段靠填完一轮再补——因为"选一个值再恢复"在非空表上不可靠，恢复不干净就是在动用户的数据。

## 循环（每一页都走一遍）
A. **看**：guard → `survey` 一次读完整页（渲染稳没稳、字段与语义坐标、控件属性、上传位）→ 条目组点满 → `probe-options` 读完所有下拉选项并触发条件字段 → 再跑一次 `survey` 确认字段齐了。仅对页面明示有范围的字段记限制原文与来源（如荣誉级别、经历类型、时间范围、条目上限），普通字段不额外建规则；长文本字段把 `maxlength`、页面明文的字数要求、校验结果三样都探出来。→ `on-site-principles.md`

   探完之后用 `plan-skeleton --from-options <探测报告>` 出骨架：探到的选项表会跟着进计划，
   面板类字段的值从那张表里挑。**不许凭印象写下拉和日期的值**——探测失败就先修探测或问用户。
   `fill` 在点开任何面板之前就会拦下没来源的值并退出 2；真要绕过（可搜索下拉的选项要打字才出来）
   给那个字段加 `options_unverified: true`，整份计划加同名开关是最后手段。
   日期这类「一个面板里并排两级」的控件，探测报告里 `kind` 会是 `cascader`、`option_groups` 为 2，
   值写成数组逐级点（如 `["2024", "9月"]`）；控件上显示的往往是拼好的另一种写法，
   所以要同时给 `display`（如 `2024-09`），回读按它比。

B. **说**：这页有哪些板块字段；我能填哪些、从 `resume.md`/`form.md` 哪段取；哪些必须用户做（登录、验证码、下一步/提交）；简历附件默认由我传、用户可以说"我自己传"；要用户给值的列表逐行收集，下拉先探选项；有后果的开关单独列。等用户说"可以"（或"这一页直接填"）。→ `collect-table.md`

C. **等**：轮到用户做的节点，说清"请你现在做 X，做完告诉我"，什么都不动；用户说完回到 A，把变化记进 `fill-log.md`。

D. **填**：初填、追加和恢复都先按已探明的字段范围筛选素材；“全部补齐”不能视为已知情的范围例外，处理办法见 `on-site-principles.md`。文本按 `controls.md` 的标准序列写入（含 blur），回读三层。自我描述、自我评价、个人简介、求职动机这类自述字段，内容只能来自 `form.md` 里按 resume-tailor 第 8 步（结构表 → 用户确认 → 初稿 → 去 AI 味改稿 → 全文过目）写出的文本；`form.md` 里没有就停下来先走那一步，把四步作为子步骤加进执行清单；简历上的一句话自评、旧网申的文本、站点解析件都不能直接贴入。用户要求沿用旧文本时，先说明网申自述和简历自评的区别、这个流程会产出什么，再照用户的决定办，并在报告里记"用户选择沿用旧文本"。写入走 `chrome_cdp.py --mark <ID> fill <计划.json>`：在投递目录 `stages/` 写这一页的计划 JSON（字段名、选择器、控件类型、目标值；长度自己守 `limits.json`，不指望 `maxlength` 拦），一条命令把整页填完并返回逐字段报告——三层回读、错误提示、面板是否收干净都在报告里。不要为每个字段现写脚本；现场写脚本只用于探测。**一份计划只写当前激活步骤里的字段**，分步表单一步一份、翻页是单独的动作（`fill` 不点下一步）。报告里有字段没填成，先看原因：说"不可见"或"找不到控件"的多半是下一步才出现的字段，翻页后另出一份计划，不要整页重跑；其余按 `control-failure.md` 处理，两次仍不对就停。→ `on-site-principles.md`、`control-failure.md`

E. **记**：`fill-log.md` 追加这一页：探测摘要、我填了什么、用户做了什么、回读结果、异常。

F. **下一页**：点前 guard，点后等页面稳定再回到 A。

## 结束
写 `fill-report.md`（`../templates/fill-report.template.md`）；写或更新 `site-notes/<域名>.md`（`../templates/site-notes.template.md`，不写个人信息）；`log.txt` 追加一行；回到原清单勾选实际完成项，关闭已回答的待决原项并同步关联记录。最后交接已填未保存、限制和仍需用户决定的事项，然后等待。
