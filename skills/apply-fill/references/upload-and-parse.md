# 上传简历与自动解析

## 每进一个表单页，先探一次有没有上传位

进入任一表单页，**先跑一次 `survey`**（它已经把五路探查固化：直接的 `input[type=file]`、shadow DOM 递归、带 `accept` 的元素、正文关键词、iframe），按结果分三种情况走：

1. **有上传位、里面是空的** → 先传附件，等解析完，做前后对比，再按 `resume.md` 逐字段重写。**不要先填字段再传附件**：站点的解析会往空字段里灌它自己认出来的内容，顺序颠倒就是先填一遍、被解析覆盖一部分、再对着一页半真半假的内容返工。
2. **有上传位、里面已经有文件** → 看下面"附件区已经有东西了"。
3. **本页没有上传位** → 记一笔继续填字段，**不要停下来问**。

"进申请页第一件事传附件"这条规则对多页面站点落不了地：有的站点把"在线简历"和"申请表"分成两页，在线简历页从头到尾没有上传入口（五路探查全为零，不是藏起来了），附件只在按岗位的申请页收。所以是按页判定，不是按流程阶段判定。

默认由 agent 代传，用的是 `chrome_cdp.py --mark <ID> upload <选择器> <文件路径>`。动手之前一句话说清传的是哪个文件、传到哪个控件，用户说"我自己传"就停下等他传完。附件默认传 PDF，站点明确说 docx 解析更好再传 docx；PDF 来自 resume-tailor 的产物（没有就说明 resume-tailor 还没跑完，这页不该开始，见 `../SKILL.md` 的前提）。

传不上去就不要绕：有的站点用自定义上传组件、`<input type=file>` 藏着或根本不存在，`upload` 报 `NO_ELEMENT` 时请用户自己传，不去找别的办法。代传只是把文件放进控件，站点的"上传中 / 解析中"仍然要等。

## 回读不到文件名不等于没传成

`upload` 把文件交给控件之后会回读 `input.files`，但**读不到不是失败**：站点在 `change` 回调里取走文件、随即清空控件是常规做法（防重复提交、释放引用），越规范的站点越会这么干。命令现在会打印"控件已被站点清空（不是失败）"并带上页面侧的佐证——有没有出现文件名、有没有进度条或状态文字、有没有新弹窗——然后退出 0。

**不要因为回读不到文件名就重传。** 有的站点上传后会弹确认框（"要不要用这份简历覆盖在线简历"这类），重传就会第二次弹出来，选错一个选项可能清空整张表。看到弹窗先只读它的文字，再决定怎么办，拿不准问用户。

## 附件区已经有东西了

探到上传控件时先读它**现在有没有文件**：文件名、上传时间、大小，页面暴露哪个就读哪个。

- 已有文件、和本次要传的是同一份（文件名或大小相同）→ 记一笔"附件已是本次要用的版本"，**不重传**。
- 已有文件但看起来是旧版本 → 告诉用户"附件区现在是 X，要换成 Y 吗"，等用户定。
- 没有文件 → 按上面的规则传。

这一步省掉的不只是一次上传，而是一次可能触发破坏性确认框的操作。

> 要验证"同名文件替换成功了没有"，得先准备一个**与现有附件不同名**的测试文件。页面在附件区往往只暴露文件名，传同名同内容的文件上去，前后完全一样，成败不可观测——那种情况下如实说"无法确认是否替换成功"，不要推断。

## 前后对比怎么做

- 上传**前**先探一次：当前页和在线简历页的字段现值，存进 `fill-log.md`。这一份是基准，缺了它就说不清哪些内容是解析填的、哪些是本来就有的。
- 等解析结束：盯页面上的状态文字（"上传中""解析中"变成文件名或"解析完成"）和字段值的变化，不要按固定秒数等。等不到就记"解析状态未知"，别写成"解析完成"。
- 上传**后**再探两页，逐字段比对，把这几件事写进 `fill-log.md` 和站点笔记：解析了没有、填到了哪一页、哪些字段被它覆盖、覆盖成了什么。
- **解析结果一律只当占位**，所有字段都要按 `resume.md` 重写。解析件的典型毛病：英文转小写或全大写、标点变半角、人名里多出空格、板块归类错、条目丢失。
- 解析把某个字段填成了我们并不打算填的内容（页面明示范围外的素材、旧简历里的经历），照 `on-site-principles.md` 的"明示的字段范围"处理：不是我们写的也要清掉或改对，不能因为"是站点自己填的"就留着。

## 几个只能实测的点

- 自动解析出来的内容在用户点保存之前只在那个浏览器的页面里，别的浏览器看到的还是空的。探到页面全空而用户说"传过了"，先问"在哪个浏览器传的、点保存了吗"，再判断是没同步还是没加载。
- 离开页面上传是否保留、"同步更新在线简历"这类复选框的效果，只有实测才知道，不要推断；能验证的当场验证，不能的写进待验证。
- 常见情况：解析只填基本信息（姓名、邮箱、学历），经历类板块要手填；附件可能允许多个文件。
